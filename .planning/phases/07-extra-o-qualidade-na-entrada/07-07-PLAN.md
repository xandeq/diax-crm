<risk_note>
## ⚠️ Nota de risco de migration (D-07 + STATE.md §"v1.2 — Pausado")

**O que é verdade hoje:** a migration `20260529134701_AddAgentFoundation` (milestone v1.2,
pausado) **já foi aplicada ao SQL Server de produção** e **já está no
`DiaxDbContextModelSnapshot.cs` local** desta branch (`chore/email-automation-versioned`).

**Consequência prática:** gerar a migration desta fase AGORA diffa limpo — o snapshot local já
reflete o estado de produção. **Não há risco na geração.**

**Onde o risco realmente está: no PUSH.** Os commits do v1.2 nunca foram pushados para
`origin/main`. Se a sessão do v1.2 for retomada e gerar novas migrations antes de a fase 7 ser
pushada, a ordem cronológica das migrations locais diverge da de produção.

**Regras operacionais deste plano:**
1. NÃO fazer `git push` — regra do projeto: push só com autorização explícita do usuário
   (auto-deploy dispara no push).
2. NÃO trocar de branch. Trabalho fica em `chore/email-automation-versioned`.
3. NUNCA usar `git add -A` (a árvore tem ~75 arquivos não rastreados em `docs/email-marketing/`).
4. Se `dotnet ef migrations add` gerar QUALQUER alteração além das 4 esperadas (website_kind,
   external_id + índice, 4 contadores, tabela mx_cache_entries), **PARAR** e reportar — é sinal
   de que o snapshot local divergiu de produção por outro motivo.
</risk_note>
